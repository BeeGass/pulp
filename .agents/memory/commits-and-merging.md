# Commits, pushes, and merges

- **Identity.** Commits use the maintainer's GitHub noreply address, `Bryan Gass <44324535+BeeGass@users.noreply.github.com>`, and are unsigned: the global signing key is unusable, so pass `-c commit.gpgsign=false` or build commits with plumbing. Set the identity through `GIT_AUTHOR_*` and `GIT_COMMITTER_*`; do not edit git config.
- **Messages.** Conventional Commits with a scope where one fits (`feat(mill):`, `fix(extract):`, `docs:`, `build(site):`, `ci:`). Lowercase imperative subject of at most 50 characters, body wrapped at 72, saying why as well as what. No emojis, and no mention of AI assistants in commits, code, or comments.
- **Shape.** Many small commits in a logical order, each passing every gate on its own. [`scripts/commits/`](../scripts/commits/) builds such a chain from a finished working tree without touching it; check each commit with [`scripts/verify-commit.sh`](../scripts/verify-commit.sh), then move the branch with `git update-ref refs/heads/dev NEW OLD && git reset -q`.
- **Pushes are the maintainer's.** The agent environment here has refused `git push`; ask the user to run `git push origin dev` rather than looking for a way around it.
- **Merging.** Work lands on `dev`; `main` moves only through a pull request from `dev` (`main-from-dev.yml` fails any other source branch). The "Protect main" ruleset requires one approving review, and the only collaborator is the admin who opens the pull request, so the maintainer merges with `gh pr merge <n> --merge --admin`. "Protect dev" requires pull requests too, and the admin bypasses it on push. Do not change rulesets or repository settings unless asked.
- **After a merge,** CI should finish green with no annotations; deprecation warnings in the run summary count as problems to fix.
